3. Исследование и применение Skill

Разбор устройства skill своими словами:

Skill test-driven-development состоит из манифеста SKILL.md и руководства writing-good-tests.md. Он формализует процедуру TDD, обязывая агента сначала создать падающий тест в отдельной итерации, убедиться в падении с ожидаемым кодом ошибки, и лишь затем создавать код реализации. Это предотвращает ложноположительные тесты и избыточную логику.

Подтверждение выполнения шагов:

  1. Phase Red: Создан тест commands_test.go со заглушкой ValidateURL, возвращающей not implemented. Вызов go test зафиксировал ошибку: FAIL: expected no error, got: not implemented.
  2. Phase Green: Реализована логика парсинга URL, лимита длины и проверки хостов в commands.go. Все тесты успешно прошли: PASS.

5. Собственный MCP: URL Inspector

Разработан автономный MCP-сервер mcp-url-inspector/server.py на базе стандартного протокола JSON-RPC 2.0 (stdio) без внешних зависимостей. Инструмент inspect_url проверяет доступность ссылки, HTTP-статус и извлекает HTML-title.

1. Успешный сценарий (Valid URL):

>> REQUEST: tools/call {"name": "inspect_url", "arguments": {"url": "https://example.com"}}
<< RESPONSE:
{
  "status": "success",
  "reachable": true,
  "status_code": 200,
  "content_type": "text/html",
  "title": "Example Domain",
  "final_url": "https://example.com"
} (isError: false)

2. Обработка ошибок (Invalid Scheme & Forbidden Host):

>> REQUEST: tools/call {"name": "inspect_url", "arguments": {"url": "ftp://files.example.com"}}
<< RESPONSE: {"status": "error", "error_type": "UNSUPPORTED_SCHEME"} (isError: true)

>> REQUEST: tools/call {"name": "inspect_url", "arguments": {"url": "http://127.0.0.1:8080"}}
<< RESPONSE: {"status": "error", "error_type": "FORBIDDEN_HOST"} (isError: true)
