# AGENTS.md

Инструкция и операционные правила для AI-агента в проекте ReadAdviserBot.

## 1. Контекст и архитектура
- **Проект:** Telegram-бот отложенного чтения на Go (Clean Architecture + DI).
- **Спецификация и назначение:** [README.md](README.md).
- **Стиль и соглашения:** [docs/style-guide.md](docs/style-guide.md).
- **Слои архитектуры:**
  - `client/telegram/` — HTTP-клиент Telegram Bot API.
  - `client/events/telegram/` — обработчик команд (`commands.go`), валидация ссылок и маршрутизация.
  - `storage/` — интерфейс хранилища (`storage.go`) и реализация SQLite (`storage/sqlite/`).
  - `consumer/` — цикл опроса и обработки входящих событий.

## 2. Команды проверки (Single Source of Truth)
- Основной скрипт проверки: `sh scripts/check.sh`.
- Перед отправкой ответа или запросом приёмки убедись, что `sh scripts/check.sh` завершается с кодом 0 (vet, тесты, сборка).
- Не ослабляй проверки и не удаляй тесты ради зелёного результата.

## 3. Ограничения и Guardrails
- **Слои:** бизнес-логика в `client/events/telegram/` обращается к хранилищу ТОЛЬКО через интерфейс `storage.Storage`.
- **База данных:** схема SQLite хранится в таблице `pages`. Не меняй схему без согласования. Сборка требует CGO (`CGO_ENABLED=1`).
- **Библиотеки:** не добавляй сторонние зависимости в `go.mod` без явного поручения. Используй стандартную библиотеку Go (`net/url`, `context`, `errors`, `strings`).
- **Git:** не делай `git commit` без подтверждения пользователя.

## 4. Протокол реализации фич (TDD Workflow)
1. **Red:** создай падающий юнит-тест в `*_test.go`, описывающий требуемое поведение.
2. **Проверка падения:** покажи, что тест падает с ожидаемой ошибкой.
3. **Green:** реализуй минимально необходимый код для прохождения теста.
4. **Проверка:** запусти `sh scripts/check.sh` и убедись, что все проверки зеленые.
5. **Приёмка:** покажи `git diff` пользователю.
