# Tree of Thoughts

- Решение, для которого нужны альтернативы: Архитектура конвейера защиты и обработки запроса в FastAPI (API-1, SEC-1, REL-1).
- Критерии выбора:
  1. Точность соблюдения HTTP-статусов по правилам `CASE.md` (413 для длины, 422 для схемы, 502/504 для LLM).
  2. Изоляция компонентов для unit-тестирования без разворачивания ASGI-сервера.
  3. Отсутствие накладных расходов на служебные эндпоинты (например, `/health`).
  4. Надежность санитизации (невозможность отправки несанитизированного diff в LLM).

## Запрос

```text
Вы — Solution Architect. Используйте методику Tree of Thoughts (ToT):
1. Сформулируйте 3 архитектурные альтернативы конвейера обработки diff в FastAPI для соблюдения правил API-1, SEC-1, REL-1.
2. Оцените каждую ветку по 4 критериям: точность HTTP-кодов, простота unit-тестирования, накладные расходы, надежность санитизации.
3. Выберите наилучшую альтернативу и обоснуйте выбор.
4. Обновите раздел «Рассмотренные альтернативы» в adr.md.
```

## Внешне описанные альтернативы

| Альтернатива | Плюсы | Минусы | Оценка по критериям (1–5) |
|---|---|---|---|
| A. Глобальный Middleware конвейер | Отсекает DoS до парсинга JSON; централизованная защита | Сложный mock в unit-тестах; накладные расходы на `/health`; сырой парсинг потока байт | 3.4 / 5.0 |
| B. Валидация целиком в Pydantic-модели | Декларативно; быстрая проверка схемы в unit-тестах | Pydantic возвращает 422 вместо требуемого правилом API-1 кода 413; мутация входного DTO | 3.6 / 5.0 |
| C. Послойный конвейер (Route Guard 413 → Pydantic 422 → Service Sanitizer SEC-1 → Resilient LLM Client REL-1) | Точные статус-коды 413 и 422; идеальная изоляция для unit-тестов каждого слоя; санитизация перед LLM без побочных эффектов | Требует разделения на 3 компонента | **4.8 / 5.0** |

## Выбор

- Выбранная альтернатива: Альтернатива C (Послойный конвейер обработки).
- Почему: Единственная альтернатива, позволяющая одновременно строго выполнить требование правила API-1 (HTTP 413 при длине > 20k) и правила валидации FastAPI (HTTP 422 при невалидной схеме), обеспечивая при этом 100% покрытие unit-тестами сервиса санитизации и LLM-клиента в изоляции.
- Как проверим: Юнит-тесты изолированных функций `sanitize()`, `ReviewRequest`, мок-тест LLM-таймаута, интеграционные тесты API на коды 413, 422 и 504.
